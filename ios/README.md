# RepairOS iOS

SwiftUI + ARKit + Metal, any ARKit iPhone (LiDAR used when present). Capture design: [areas/app.md](../areas/app.md).

- Built with Xcode 27.2 (27B48) and its Metal Toolchain (`xcodebuild -downloadComponent MetalToolchain` once), Swift 6
  (strict concurrency), deployment target iOS 18.0. Device builds: `-configuration Release` only.
- `RepairOS/Contracts/Contracts.swift` is generated by `make codegen` from `spec/contracts/` (quicktype). Never edit
  it; `make codegen-check` fails on drift.
- Signing: copy `Config/Signing.example.xcconfig` to `Config/Signing.xcconfig` (gitignored) and set `DEVELOPMENT_TEAM`
  (a free Personal Team works; profiles last 7 days). Build with `-allowProvisioningUpdates`; on first install, trust
  the developer on the phone (Settings → General → VPN & Device Management). Uninstalling the last app from the team
  removes that trust again.
- The phone holds no keys; it talks only to the backend gateway (A6).

## Working from Windows (no Mac)

You can write, build, test and install this app without owning a Mac.

- **Edit** in VS Code with the Swift extension. You get syntax colouring and SourceKit for plain Swift only; the iOS
  frameworks (SwiftUI, ARKit, CoreBluetooth, Metal) do not resolve on Windows, so red squiggles on them are normal.
  The compiler is the CI.
- **New files need no project edits.** The project uses a synchronized root group: any `.swift` file under
  `ios/RepairOS/` or `ios/RepairOSTests/` is in the target as soon as it exists.
- **Build and test:** push a branch. The `iOS` workflow (`.github/workflows/ios.yml`) builds the app for the
  simulator and runs the unit tests on GitHub's macOS runner (free for this public repo). Watch it with
  `gh run watch`; the `.xcresult` bundle and the full log are kept as an artifact for 14 days.
  The CI uses the `xcode-27` runner label (Xcode 27.2, 27B48, the same as above; the newest Xcode on the image is
  selected and Metal toolchain downloaded) and the newest iPhone simulator on it. First green run: about 20 minutes
  (19 minutes build and test; 273 tests in 72 suites, 11.5 minutes of them the tests themselves).
- **Install on your phone:** run the workflow by hand (Actions > iOS > Run workflow, tick `archive`). It needs four
  repository secrets: `APPLE_CERT_P12_BASE64` (a signing certificate exported as .p12, base64), `APPLE_CERT_PASSWORD`,
  `APPLE_PROVISIONING_PROFILE_BASE64` (a profile that lists your phone) and `APPLE_TEAM_ID`. The job uploads an `.ipa`;
  install it from Windows with Sideloadly or AltServer. A free Apple ID gives a 7-day certificate and 3 apps; a paid
  Apple Developer account allows TestFlight and 90-day builds. Turn on Developer Mode on the phone (Settings > Privacy
  and Security).
- **Install on your phone with a free Apple ID (no secrets, no Developer account):** the `ipa` job in the same workflow
  builds a Release app for a device with code signing off and uploads `RepairOS-unsigned.ipa` (artifact
  `RepairOS-unsigned-ipa`, kept 14 days). Then:
  1. Download it: Actions > the run > Artifacts, or `gh run download <run id> -n RepairOS-unsigned-ipa`.
  2. On Windows install iTunes and iCloud from Apple's own site (apple.com/itunes and the iCloud for Windows download
     linked from Apple Support). The Microsoft Store versions do not work: Sideloadly rejects them.
  3. Install Sideloadly (or AltServer), plug the phone in, tap Trust on the phone, sign in with your Apple ID in
     Sideloadly, and drag the `.ipa` onto it. Sideloadly signs it with a free 7-day certificate as it installs.
  4. On the phone turn on Developer Mode (Settings > Privacy & Security > Developer Mode; it restarts the phone), then
     trust the certificate (Settings > General > VPN & Device Management > your Apple ID > Trust).
  5. The app lives 7 days. Re-sideload the same way to renew it (data in the app is kept when it is installed over
     itself). A free Apple ID allows 3 sideloaded apps at once.

  Measured on the first green run: the `ipa` job takes about 3 minutes and the .ipa is 4.3 MB (a 15.7 MB arm64
  binary inside); the `test` job took 17 minutes.

  What has not been tried: the artifact is verified to hold `Payload/RepairOS.app/Info.plist` and the `RepairOS` binary
  (below), but nobody has yet installed it through Sideloadly or AltServer from Windows, or run it on a phone. If
  Sideloadly refuses it, the message is the thing to report.
- **Get a session off the phone** (so it can be handed to the design engine as one zip of
  `Documents/sessions/<id>/`: `app_session.json`, `scans/<scan_id>/scan_package.json` + the PLY + keyframes,
  `stills/`, `readings/`):
  - *Files app:* Files > On My iPhone > RepairOS > sessions > long-press the session folder > Compress > share the zip.
    The app sets `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace`, which is what makes the folder visible.
  - *In the app:* Home > long-press a saved scan > Share session. It zips the folder (`SessionArchive`: a stored
    zip whose entries are relative to the session root, because Foundation's `.forUploading` zipper wraps everything in a
    top folder named after the session, which the importer does not expect) and opens the share sheet (AirDrop, Files,
    Mail). Only files already in the folder are included. CI opens the zip with Python's `zipfile` and checks the root
    entries.
- **Logs:** `devicectl` needs a Mac. Instead open the Files app on the phone > RepairOS > `sessions/<id>/` and share
  `diag.jsonl` (the folder is visible there, see "Capture layout").
- **Fallback:** for Instruments or a step-through debugger, rent an hourly cloud Mac mini and use the commands above.

## Build and run

```
cd ios
xcodebuild -project RepairOS.xcodeproj -scheme RepairOS -configuration Release -jobs 4 \
  -destination 'id=<udid>' -allowProvisioningUpdates build
xcrun devicectl device install app --device <udid> <DerivedData>/Build/Products/Release-iphoneos/RepairOS.app
xcrun devicectl device process launch --device <udid> com.rohankilaru.repairos [flags]
```

Developer launch flags: `--record-raw-frames` (Turn it: save the tracker's input at 5 Hz, ≤ 600 frames, in
`<session>/raw/` for `tools/handheld/run.sh replay`), `--turn-it` (start the scanner in Turn it), `--handheld-no-segmentation` / `--handheld-hand-pose` (Turn it's
person mask: Vision hand pose instead of, or with, ARKit segmentation), `--gateway <url> --pairing-code <code>` (pair without typing), `--autostart-scan` (open a
scan at launch), `--auto-scan` (press Scan after 3 s), `--run-still-probe`, `--object-capture` /
`--no-object-capture` (Apple Object Capture engine, off by default), `--open-session <session_id>` (open a saved scan
at its report), `--show-on-object` (with it: open "Show on object" once the report is up), `--demo-replay` (with it:
play it as a Demo replay), `--demo-replay-session <session_id>` (turn Demo replay on for that scan). Unit tests run on
the simulator; shut it down after (`xcrun simctl shutdown all`).

## The report

**Report stage** (`Report/Stage/`, on by default; `--old-report` shows the previous layout): the scan sits on a dark stage with the report sheet over it. The hero is the photo-real recreation (`Report/Recreation/`: the phone's shell, built when a report opens, or the gateway's on `recreation_ready`) when the scan has one, else the hero below. Markers are kept apart on screen; the lasso button circles a spot to look closer at (saved in `<session>/inspect_targets.json`; Continue scanning aims its "Move closer here" marker there). Gallery: `--ui-screen stage|stage-landing|stage-wait|stage-old --ui-session <dir>` (`--ui-build-shell`, `--ui-blobs <dir>`).

The hero at the top follows the backend's choice (`hero` in `mesh_ready`, `/pipeline`, the report's `mesh`):
`points` = its cleaned cloud (`GET /v1/scans/{id}/cloud`), `mesh` = its mesh (`GET /v1/scans/{id}/mesh`, cropped to the
locked box), `photos` = the best still with the numbered crop boxes and a strip of the others; until it chooses, the
phone's own cloud. The 3D view turns slowly until touched and shows the top three problems; "+N" lists the rest.
**Show on object** puts the numbered problems on the real object, from whichever lands first: the saved
`world.arworldmap` relocalising, or the object alignment (`Report/ObjectAligner.swift`: live LiDAR points around the
view registered to the saved in-box cloud, gravity + plane start, 24-yaw search, 4-DOF point-to-plane ICP, accepted on
inliers, RMS, coverage and visibility, and only when two attempts in a row agree within 1.5 cm). The world map, when
it matches, takes over. Past 6 s it says so and offers the 3D view. `diag.jsonl` logs `ar_align_*` and
`ar_markers_*` (time to land, which answer, the side it was seen from, object-vs-map offset). Live events (`GET /v1/sessions/{id}/events`) drive the scanner's "Looks like" chip
(tap to correct; kept as `objectName` on the session) and its "areas checked" count.

**Voice** (`RepairOS/Voice/`, backend `repairos/voice/`): Lea says one or two sentences when a report lands (verdict, top
problem, first safety note), short scan cues paced by `CueLimiter` (one line per 4 s, never overlapping, never the same
line twice in 10 s; the fixed lines are fetched at launch and cached), and talks on the report ("Talk to Lea": hold to
talk, or tap for hands-free; answers stream sentence by sentence from `POST /v1/voice/converse`). "Hey Lea" is heard
on the phone only (Apple on-device recognition, foreground, Settings toggle, paused during capture and while Lea
speaks). Speech comes from the gateway (Cartesia; the key stays on the backend) or, without it, from the phone.
Mute: the speaker button on the scan and report screens. Flags: `--voice-speak-report` (say a saved report on open,
logs `voice_report`), `--voice-muted` / `--voice-unmuted`, `--voice-frame-probe` (a cue every 4.5 s during the scan,
logs `voice_frame_probe` frame times), `--wake-during-scan` (keep "Hey Lea" on during capture, to measure). diag.jsonl:
`voice_report`, `voice_cue`, `voice_turn`, `voice_ask`. "Scan with Lea" is an App Shortcut (Siri).

**Demo replay** (Settings: tap the version line five times): plays a saved scan from this phone and its saved report
with no network. Every report saves its crops in `<session>/crops/`, so any scan with a report can be replayed.

## The scan

Point at the object → **Scan** → walk around while the live LiDAR point cloud fills in → **Done**. The object under
the screen centre is locked automatically (the cloud brightens on it and dims elsewhere); a tap corrects it.
Photos, torch and upload are automatic. Code: `RepairOS/Capture/` (`ScanSession`, `PointCloudRenderer` +
`PointCloud.metal`, `BoxFitter`, `QualityGate`/`TorchRule`), stills in `RepairOS/Closeups/`.

**Scan the bottom** (`RepairOS/Capture/Handheld/FlipSegment.swift`, `FlipAligner.swift`): after the main scan (a chip
on the scanner once a few sides are covered, or the report next to Continue scanning) Lea says "Now flip it over and
give me a quick look at the bottom": a 10–20 s continuation in its own ARKit session (no room map: the object moved),
segment `reason: flipped`, `object_moved: true`. Every ~2 s its in-box cloud is registered to the main scan's saved
cloud in 6 DoF (24 cube orientations × 8 turns, short ICP each, the best refined; it must have been flipped, nothing
inside the table, the underside on the table's footprint; colour picks between poses the shape cannot tell apart,
else refused as ambiguous). Two agreeing attempts line it up: the main cloud appears around the flipped object, Lea
says "Lined up with the first scan", and the segment records `aligned: true`, `transform_to_segment0` (row-major,
this segment → segment 0, metres) and `transform_quality`. Unsure: the backend registers it; until it applies the
transform, findings of moved segments are listed but not placed. diag: `flip_start`, `flip_align` (each attempt),
`flip_aligned`. Synthetic: `tools/handheld/run.sh flip box|board|plain [trials]`.

**Turn it** (developer flag `--turn-it`, off by default): for a small object, the person sets it down, taps "Turn it in your hand",
taps Scan, then holds it up and turns it (or flips it for the underside) while the phone stays roughly still; the
scanner also suggests it when a small object (< 25 cm) is scanned from one spot. `ObjectTracker` follows the object's
6-DoF pose at 15 Hz on a background queue: LiDAR depth masked to the box (+3 cm), minus the person (ARKit
`.personSegmentationWithDepth` alongside `.sceneDepth`, else Vision hand pose) and the table, point-to-plane ICP
against the growing object model, plus FAST corners with steered binary descriptors lifted to 3D and a rigid
consensus fit (they hold a symmetric or flat object where ICP slides); directions nothing pins down keep the
prediction and lower the pose quality. Lost → "Hold it still for a moment", relocalised from the last pose, the
features or 24 turns about the centre, accepted when two frames agree. Everything is in the OBJECT frame (= ARKit
world at the lock): the cloud is fused there on the GPU (`Handheld.metal`) and drawn where the object is now; stills,
keyframes and the dial use the camera relative to the object (a view from below fills the dial's ring and is
recorded as `b<ring>s<sector>`); records carry `pose_source: object_tracked` + `pose_quality`. The backend cuts
nothing at the support plane for such a scan. Synthetic accuracy and the Mac replay: `tools/handheld/run.sh`;
after a phone test: `python3 -I tools/handheld/diag_summary.py <session folder>`. diag: `handheld_start`,
`handheld_stats` (5 s), `handheld_lost`, `handheld_recovered`, `handheld_suggested`.

The live cloud's unprojection and colour conversion are adapted from Apple's sample "Displaying a point cloud using
scene depth" (licence: `RepairOS/Capture/ThirdParty/AppleScenePointCloud/LICENSE.txt`).

## Capture layout

Everything a capture records, in the phone's app container (`Documents/sessions/<session_id>/`, visible in the Files
app), uploaded to the gateway and replayable (`samples/README.md` layout). Every record carries its capture
`segment` (0 = the object as it stands; 1+ after a flip; absent = 0).

```
<session_id>/
  app_session.json                     the app's own record (status, still ids, engine)
  upload.json                          upload progress (blob refs per file), for resuming
  diag.jsonl                           one JSON line per event (see below)
  world.arworldmap                     ARWorldMap at Done (relocalised by "Show on object" and "Continue scanning")
  report.json                          the latest report (opens offline)
  crops/<sha256>                       the report's crop images, saved for offline and Demo replay
  scans/<scan_id>/
    scan_package.json                  ScanPackage (spec/contracts/scan-package.schema.json)
    points_arkit_world.ply             in-box LiDAR cloud: binary LE, xyz float32 m + rgb uint8, ARKit world (Y up)
    mesh_gateway.ply                   the gateway's mesh of the scan, once fetched (same frame)
    kf_NNNN.jpg                        ~5 Hz keyframe: 640 px RGB, sensor orientation
    kf_NNNN_depth.png                  its LiDAR depth, 256×192 uint16 mm (0 = none)
    kf_NNNN_conf.png                   its ARKit confidence, 256×192 uint8 (0/1/2)
  stills/
    <scan_id>_sN.json                  Still (spec/contracts/still.schema.json)
    <scan_id>_sN.jpg                   12 MP JPEG q0.9, sensor orientation, no EXIF/GPS
    <scan_id>_sN_depth.png             depth from the nearest regular frame (high-res frames carry none)
    <scan_id>_sN_conf.png              its confidence
```

- **Keyframes** (`scan_package.keyframes[]`): pose (`camera`, ARKit world, camera looks down −Z), intrinsics for the
  640 px image (the depth map shares the camera: scale them by 256/640 for depth pixels), `timestamp_s`,
  `exposure_s`, `tracking_state`, `segment`. About 0.1 MB per frame, ~60 MB per 2 minutes.
- **Stills**: pose, intrinsics at the still's size, `captured_at`, `exposure_s`, `iso`, `depth_file` +
  `confidence_file` + `depth_gap_ms`, `tracking_state`/`pose_reliable`, `segment`, `sharpness`, `torch_level`/
  `torch_on`, `low_light`, `view_cell` (coverage cell around the object).
- **Scene**: `crop_box` (the locked object box), `support_plane` (the table's plane anchor: row-major transform +
  extent), `gravity_arkit_world` = [0, −1, 0] (gravity-aligned session), `points_file` + `point_count`.
- **diag.jsonl**: `scan_start`, `first_points` (ms after start), `scan_tapped`, `lock` / `lock_failed`
  (ms, cloud and in-box point counts), `still` (ms, depth gap, ISO, exposure, torch), `heartbeat` every 5 s (cloud
  and in-box points, stills, keyframes, display frame time mean/p95, torch, tracking), `torch*`, `upload_error`
  (with the gateway's body), `world_map_saved`, `finish`. Pull it:
  `xcrun devicectl device copy from --device <udid> --domain-type appDataContainer --domain-identifier
  com.rohankilaru.repairos --source Documents/sessions/<id>/diag.jsonl --destination .`
